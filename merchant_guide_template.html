KuickPay Embedded Checkout

Complete guide for integrating seamless Modal and Inline card payments directly within your web store.

Target Audience: Merchant Engineers & Developers
Format: Embedded Iframe + Universal JS SDK
Security: HMAC SHA-256 Signed

1 Overview & Architecture

KuickPay Embedded Checkout allows merchants to take customer payments directly inside their website without a disruptive full-page browser redirect. Customers remain in your storefront while entering payment credentials inside a secure, PCI-compliant KuickPay iframe.

1
Create Session

Your server signs order data and creates a session via KuickPay API.

2
Open Embed

Frontend launches checkout in a Modal Dialog or Inline Container.

3
Customer Pays

Customer enters card securely inside the KuickPay iframe.

4
Verify & Confirm

Frontend gets event; your server securely confirms with KuickPay Status API.

Embed Mode Behavior & Appearance Recommended Use Case
Modal (Popup) Default Renders an overlay dialog centered over your page with background blur. Closable by customer via ✕ button or Escape key. Standard e-commerce checkouts, Quick Buy buttons, cart drawers.
Inline (On-Page) Seamless Embeds smoothly into a designated <div> element on your page. Automatically adapts height via resize events. Single-page checkouts, multi-step checkout accordions, kiosk displays.

2 Credentials & Environments

KuickPay provides each merchant with four key integration parameters:

  • Company ID: Your unique merchant identifier (e.g. 10010).
  • Secured Key: A secret 256-bit key used to compute request HMAC signatures and HTTP Basic Auth.
  • API Base URL: Backend gateway endpoint for session creation & transaction verification.
  • Checkout Base URL: Frontend domain hosting the embedded checkout form (/embed/[sessionId]) and the universal SDK script (kuickpay-checkout.js).
Environment API Base URL (baseUrl) Checkout Base URL (checkoutUrl)
Local Development https://prod-api.kuickpay.com http://localhost:3000
UAT Sandbox https://sandbox-api.kuickpay.com https://testcheckout.kuickpay.com
Production https://prod-api.kuickpay.com https://checkout.kuickpay.com

3 Step 1: Create Payment Session (Backend)

When a customer clicks checkout, your backend server must create a session. Never perform session creation directly in client-side code, as doing so would expose your secret key.

Endpoint: POST {API_BASE_URL}/checkout/api/session

ℹ️
HTTP Basic Authentication
Send header Authorization: Basic base64(CompanyID:SecuredKey) with Content-Type: application/json.

Payload Fields

Field Type Description
companyid string Your KuickPay Company ID (e.g., "10010").
orderid string Unique order identifier generated by your system (e.g. "ORD-1718902").
amount string Order total formatted to 2 decimals (e.g. "250.00").
amountPayable string Net payable amount including tax/shipping (e.g. "250.00").
currency string Currency code: "AED" (United Arab Emirates Dirham) or "PKR".
timestamp string Current ISO 8601 string (e.g. "2026-11-16T12:00:00.000Z").
transactiondescription string Brief description of items purchased.
returnurl string Your storefront return URL (used if fallback redirect is triggered).
signature string Base64-encoded HMAC-SHA256 signature of canonical string.

Signature Calculation

Assemble the canonical string in the exact order below, separated by pipes (|), and hash it with your SecuredKey:

// 1. Construct canonical string:
const canonical = `${companyid}|${orderid}|${amount}|${amountPayable}|${timestamp}`;

// 2. Hash using HMAC SHA256 and convert to Base64:
const signature = CryptoJS.HmacSHA256(canonical, securedKey).toString(CryptoJS.enc.Base64);

Session API Response

{
  "success": true,
  "responseData": {
    "sessionID": "KP-SESS-9A82FC-2026",
    "redirectURL": "https://checkout.kuickpay.com/embed/KP-SESS-9A82FC-2026",
    "companyID": "10010"
  }
}

Return the sessionID to your frontend code to trigger the embedded checkout.

4 Step 2: Embedded Checkout (Client-Side)

Merchants can implement the embedded checkout using either the Universal JS SDK or React Components.

Option A: Universal JavaScript SDK (Any Website / HTML)

Include the lightweight SDK script in your page <head> or layout:

<script src="https://checkout.kuickpay.com/kuickpay-checkout.js"></script>

1. Modal Popup Mode:

// Trigger when user clicks your "Place Order" button
KuickPay.open({
  baseUrl: 'https://checkout.kuickpay.com',
  sessionId: sessionID,            // Received from Step 1
  mode: 'modal',                    // 'modal' popup dialog
  closeOnBackdrop: true,
  closeOnEscape: true,
  onReady: function() {
    console.log('Checkout iframe loaded successfully');
  },
  onSuccess: function(data) {
    // data: { orderID, transactionID, amount, currency, responseCode: "00" }
    window.location.href = `/kuickpay-return?orderID=${data.orderID}&transactionID=${data.transactionID}&status=00`;
  },
  onFailed: function(error) {
    alert('Payment declined: ' + (error.message || 'Please try again'));
  },
  onClose: function() {
    console.log('Customer dismissed modal');
  }
});

2. Inline Embed Mode:

<div id="kuickpay-mount-point" style="min-height: 620px;"></div>

<script>
KuickPay.open({
  baseUrl: 'https://checkout.kuickpay.com',
  sessionId: sessionID,
  mode: 'inline',
  target: '#kuickpay-mount-point',   // CSS selector for container
  onSuccess: function(data) {
    window.location.href = `/kuickpay-return?orderID=${data.orderID}&transactionID=${data.transactionID}&status=00`;
  },
  onFailed: function(error) {
    alert('Payment failed: ' + error.message);
  }
});
</script>

Option B: Pure React / Next.js Components

Merchants using React or Next.js can drop ready-made JSX components into their component hierarchy without external script tags:

import KuickPayCheckoutModal from '@/app/components/KuickPayCheckoutModal';

<KuickPayCheckoutModal
  isOpen={isModalOpen}
  sessionId={sessionId}
  baseUrl="https://checkout.kuickpay.com"
  onClose={() => setIsModalOpen(false)}
  onSuccess={(data) => {
    setIsModalOpen(false);
    window.location.href = `/kuickpay-return?orderID=${data.orderID}&transactionID=${data.transactionID}&status=00`;
  }}
  onFailed={(err) => alert(err.message || 'Payment failed')}
/>

5 postMessage Event Protocol

The embedded iframe communicates bi-directionally with the merchant window using the browser postMessage standard. All events originating from KuickPay carry source: "kuickpay-checkout".

Event Type When Triggered Payload Structure
KUICKPAY_READY Iframe rendered checkout form and is ready for customer input. { source, type: "KUICKPAY_READY" }
KUICKPAY_SUCCESS Transaction authorized and successfully captured by 3DS gateway. { source, type: "KUICKPAY_SUCCESS", orderID, transactionID, amount, currency, responseCode: "00" }
KUICKPAY_FAILED Card declined, 3DS failed, or insufficient balance. { source, type: "KUICKPAY_FAILED", message, responseCode }
KUICKPAY_CLOSE Customer clicked close button or backdrop overlay. { source, type: "KUICKPAY_CLOSE" }
KUICKPAY_RESIZE Checkout content height changed (Inline mode automatic adjustment). { source, type: "KUICKPAY_RESIZE", height: 680 }
KUICKPAY_ERROR Session expired or network connectivity error occurred. { source, type: "KUICKPAY_ERROR", message }

6 Step 3: Transaction Inquiry & Verification

Mandatory Security Step: Client-side events (such as KUICKPAY_SUCCESS) can theoretically be spoofed in a browser console. Your backend server must always call the KuickPay Status API before releasing digital goods or fulfilling inventory.

Endpoint: POST {API_BASE_URL}/checkout/api/status

Authentication: Authorization: Basic base64(CompanyID:SecuredKey)

// Server-side verification request payload:
{
  "sessionID": "KP-SESS-9A82FC-2026",
  "redirectURL": "https://checkout.kuickpay.com/embed/KP-SESS-9A82FC-2026",
  "companyID": "10010"
}

Status API Response:

{
  "responseCode": "00",
  "responseDescription": "Transaction Successful",
  "transactionId": "TXN-2026-981240"
}
✅
Order Confirmation Condition
Mark order as paid only when responseCode === "00" is returned directly from the backend status API.

7 Security & Production Go-Live Checklist

Status Item Requirement
🔒 Secured Key Protection Store SecuredKey in environment variables (e.g. .env.production) on backend. Never bundle in JS.
🛡️ Message Origin Verification Check event.data?.source === 'kuickpay-checkout' on all postMessage listeners.
🔐 HTTPS Everywhere Both your storefront and return URL must be served over valid TLS/HTTPS.
💵 Amount Verification Verify returned amount matches the order amount stored in your database before fulfillment.
🚀 Switch to Production URLs Point API to prod-api.kuickpay.com and Checkout to checkout.kuickpay.com.
